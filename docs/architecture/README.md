## Reading the C4 levels

- **L1 Context:** the system (Nive) as a black box among people and external
  systems.
- **L2 Containers:** deployable or compilable units — here, the **crates**.
- **L3 Components:** the blocks inside a container — here, the **Rust modules**.
- (L4 Code is left to the class and state diagrams in `runtime-flows.md` and
  `design-system.md`.)

**Colour legend:** blue = a Nive element · grey = external (Iced, the OS, the
registry).

## Workspace responsibilities

- `nive-core`: dependency-free presentation and interaction contracts shared by
  the UI and runtime layers.
- `nive-ui`: design tokens, semantic themes, reusable widgets, bundled fonts,
  and icon management.
- `nive-runtime`: application lifecycle, window management, asynchronous state,
  feedback, and optional devtools integration.
- `nive-runtime-derive`: proc macros supporting runtime inspection.
- `nive-workbench`: professional desktop shell composition built from Nive UI
  primitives, with optional runtime adapters.
- `nive`: umbrella crate and prelude surface.
- `nive-cli`: project scaffolding and provider-neutral icon workflows.

Keep dependency direction toward neutral contracts. `nive-core` must not depend
on Iced, UI vocabulary, or application lifecycle types. UI composition remains
in `nive-ui`; runtime state and lifecycle behavior remain in `nive-runtime`;
workbench-specific shell composition remains in `nive-workbench`.
