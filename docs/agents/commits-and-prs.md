# Commit And PR Guidelines

## Commits

Use Conventional Commit style:

- `feat: ...`
- `fix: ...`
- `refactor: ...`
- scoped variants such as `refactor(workspace): ...`

Keep messages imperative and specific.

## Pull Requests

PRs should include:

- a short problem statement
- a summary of user-visible changes
- linked issues or specs when applicable
- screenshots or recordings for UI work

Call out schema changes, new migrations, and document parser protocol updates explicitly.
